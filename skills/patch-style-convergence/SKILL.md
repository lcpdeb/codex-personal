# 补丁风格收敛

在保护已确认基线和权责边界的前提下，将当前责任范围内的实现收敛为整体理解成本最低、最符合当前仓库惯用方式的改动。

## 执行

1. 先确认本次权威基线；当前会话尚未确认基线时，使用 `baseline-attribution` 请用户明确确认，确认前不读取仓库或比较代码。
2. 基线确认后，读取适用的 `AGENTS.md`、专项规则、基线完整快照、当前差异、受影响文件和邻近同类实现，区分基线范围与当前改动引入、扩大或恶化的范围。
3. 明确补丁必须保持的输入、输出、副作用、失败语义、所有权和生命周期；缺少会改变这些内容的决定时停止并询问用户。
4. 在当前责任范围内比较候选实现，以职责清晰、数据流直接、状态唯一、接口语义准确、生命周期闭合和隐含规则最少为主要标准。代码行数、文件数量和差异大小只作为次要参考。
5. 搜索拟修改符号的全部调用方，优先删除无用代码、复用现有实现和标准能力；需要重构或调整接口时，以降低整体理解成本和保持权责清晰为依据。
6. 默认只修改当前改动负责的代码，使其适配基线已有的设计、共享接口和功能。不得为了局部方便，将当前责任转移给基线代码或扩大共享契约。
7. 修改基线设计、共享接口、范围外代码或已确定功能前，说明必要性、影响范围、全部调用方、替代方案和验证方式，并取得用户对本次跨边界修改的明确授权。
8. 因解释存在改动的代码或文件而触发时，在说明原代码目的与本次调整原因的同时，按冗余收敛检查项指出可删减的多余改动并给出最小写法；收到用户的明确修改授权后，再完成补丁写入，并静态检查差异、声明与定义、调用方和引用关系。构建与测试仅在用户明确授权后执行。

## 冗余收敛检查项

逐文件、逐块检查当前补丁时，主动排查并消除以下冗余：

1. **函数签名与入参去重**：已有入参对象或基类接口可直接提供所需数据时，不额外增加子字段入参；多派生类型共用的数据优先通过基类接口获取，省去调用处的类型判断分支。
2. **数据对象与状态归属去重**：
   - 数据对象只保留自身属性，删除为配合外层角色判断或界面禁用而塞入数据对象的辅助状态字段。
   - 同一状态在子项、模型和视图层重复保存，或同时存在对象成员与外层同名字段时，合并为唯一事实源，并一并删除仅用于在两个副本间搬运数据的同步函数。
   - 容器级当前选中项或默认状态在构造时直接初始化为有效对象，删除因未初始化而在下游各处增加的判空分支。
3. **接口声明与拷贝范围去重**：搜索补丁中新增接口成员、方法或拷贝字段的全部调用方；无调用方通过该接口访问的声明直接还原为基线，特定用途的复制方法不追加与该用途无关的字段拷贝。
4. **控制流与重复保护去重**：
   - 状态在初始化和输入入口已由约束保证合法时，普通读取、状态切换和单项监听直接使用该值，删除重复的强制覆盖、原地回写或回滚分支。
   - 条件与赋值直接表达目标状态，不用反向过滤“跳过某项”代替明确赋值，也不在循环外层叠加底层赋值方法已内置的新旧值相等判断。
   - 在基线原有分支或循环上扩展条件时，保留基线原有的控制流结构和查找位置，删除顺手夹带的无依据判空兜底或外提查找。
5. **命名随职责收敛同步更新**：删减函数或变量的附加职责后，同步更新其名称，使其准确反映剩余的实际操作。

## 边界

- “当前责任范围”指当前改动引入、扩大或恶化的代码和行为；基线既有且未受当前改动影响的内容保持不动。
- 最小实现以整体理解成本为准。更大的局部重构可以是更合适的实现，但跨越基线或权责边界仍须用户明确授权。
- 不为未来需求新增抽象、配置、依赖、重载、兼容层或测试脚手架。
- 不把个人偏好覆盖到已有仓库规则之上；仓库规则和稳定的邻近模式是风格事实源。
- 不借收敛之名修复范围外缺陷；发现后单独报告。
- 交付时列出实际修改、静态证据和未验证行为。
