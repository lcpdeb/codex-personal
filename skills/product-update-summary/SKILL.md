# 更新日志查阅与总结

## 查阅范围和事实来源

- 查看用户指定的更新日志原始页面；未指定时优先查找产品或项目的官方更新日志。搜索结果可用于寻找页面，最新版本和日期以实际读取的原始页面为准。
- 承接已有对话：再次查看时，以上次讨论的版本或日期为比较起点，覆盖其后发布的所有相关版本；没有新版本时说明核查时看到的最新版本和日期。
- 展开详情，阅读新增功能、改进、修复、维护说明和 Full Changelog 等完整记录。按用户要求的范围覆盖；完整记录存在时逐条覆盖，不因内容偏底层而省略。
- 以原文为依据，保留影响含义的范围、条件、版本和实验性状态。原文只有简短标题时，解释标题含义，不虚构原因、效果或使用条件。记录存在先后调整时保留顺序；最终状态以发布说明为依据。
- 页面或部分详情无法读取时，说明已查阅内容和具体缺口。查阅任务保持只读；提供安装命令时注明来源，安装、升级或修改配置需有明确授权。

## 输出顺序

1. **更新结论**：说明是否有新版本、版本号、发布日期，以及与前次讨论的关系；简要概括用户最关心的变化，附原始来源链接。
2. **详细更新内容**：依实际内容组织新增功能、使用体验、问题修复、安全和维护等章节。用具体场景说明行为、条件和结果；原文提供编号时保留编号。
3. **完整更新记录**：按主题逐条整理 Full Changelog 或等价记录，保留原始编号或链接。相关条目可分组，但保留各项区别；收录测试、依赖升级和内部整理，说明其性质。没有完整清单时说明来源实际提供的内容。
4. **章节性总结**：在完整记录之后，按产品适用场景归纳，例如日常使用、稳定性与恢复、连接、安全与权限、开发与管理；章节按实际内容调整。

用户另有范围或篇幅要求时，遵循用户要求。用户仅询问是否更新或某项具体内容时，直接回答所问范围。

## 表达方式

- 使用自然、通俗的中文，先说具体对象的行为和结果。英文产品名、命令及专业名称保留原文，首次出现时结合当前场景解释。
- 标题、表头、段落标签和正文使用名词短语或陈述句，不使用“有什么变化”“更新了什么”“在做什么”“修复了什么”“新增了什么”等提问式设问。
- 用具体行为解释改进，例如“恢复对话时保留已确认的权限设置”；避免用“优化”或“增强”代替具体内容。
- 区分用户可见功能、实验性功能、内部维护和测试；不把内部准备工作说成用户已经可以使用的功能。
